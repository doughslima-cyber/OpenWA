  `() => clearTimeout(timer)` and depends on `[data, refetch]`; a chat change changes the query key, so `data`
  changes (to the new chat's answer or `undefined`) and the old timer is cleared before a new one is set, and unmount
  runs the same cleanup. `refetch` is stable (react-query observer method). With `closesAt` already past, the delay is
  floored at 1000 ms, so at most one re-read per second; once the window answers `open: false` the early return sets no
  new timer, and if the server keeps answering the same `open: true` payload, react-query's structural sharing keeps
  the same `data` reference, the effect does not re-run, and no further timer is set. There is no tight loop. None of
  this beyond C59's single case is asserted (Test policy row 4).
